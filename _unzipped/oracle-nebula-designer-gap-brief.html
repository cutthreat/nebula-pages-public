Главный разрыв

Сейчас пользователь может увидеть экспертов и попасть в чат, но дизайн не объясняет коммерческий контракт: что именно покупается, как проходит оплата, как задаётся вопрос, что происходит во время платной сессии и как пользователь возвращается к результату.

Порядок работы дизайнеру

  1. Сначала перевести HTML onboarding prototype в реальный Figma frame для desktop.
  2. Затем нарисовать один полный happy path: registration -> onboarding -> advisor match -> starter package -> checkout success -> question intake -> paid chat/async answer -> transcript -> follow-up.
  3. После этого закрыть P0 failure/boundary states: fail/pending payment, no credits, advisor unavailable, low credits, delayed answer, refund/support/report.
  4. Только потом переходить к P1 и P2.
